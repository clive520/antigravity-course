架構設計關鍵問答

架構關鍵問答：為什麼選 Supabase？Workers 又是什麼意思？

理解技術選型的底層邏輯，具備真正的系統架構師思維

🤔
為什麼選 Supabase 而非 Cloudflare Vectorize？
  • 「內文與向量一體化」：Supabase 每一筆紀錄同時存有 Markdown 手冊長文與 768 維向量，1 趟查詢直接帶回文章！
  • Vectorize 缺陷：Vectorize 只存向量數字不存長文，查詢後 Workers 還得再去 D1 或 KV 做「兩階段二次撈取」，架構繁瑣。
  • 混合搜尋：手冊中的「請假代碼 E-102、天數 8 天」，Supabase 支援關鍵字 + 向量雙軌檢索最準確。
⚡
Workers 所指的又是什麼意思？
  • 邊緣無伺服器計算：代碼複製在全世界 330+ 城市，離員工最近，0 毫秒冷啟動。
  • 金鑰守門員（金鑰不落地）：Gemini API Key 安全鎖在後端環境變數，員工按 F12 絕對看不到。
  • RAG 管線總指揮：編排轉向量、查庫、組裝提示詞、防幻覺過濾的前後端核心樞紐。

11-2 資料庫建置

Supabase 向量資料庫建表與 RPC 檢索預存程序

在 SQL 編輯器中一鍵完成向量資料表與餘弦相似度查詢函數

-- 1. 開啟向量擴充套件
create extension if not exists vector;

-- 2. 建立手冊知識庫資料表（內文、出處 metadata 與 768 維向量）
create table handbook_documents (
  id bigserial primary key,
  content text not null,                  -- 手冊段落原始文字
  metadata jsonb not null,               -- 出處標籤（{"doc": "差勤管理", "section": "4.1"}）
  embedding vector(768) not null        -- 768 維特徵向量
);

-- 3. 建立餘弦相似度檢索預存程序 (RPC: match_handbooks)
create or replace function match_handbooks (query_embedding vector(768), match_count int default 4)
returns table (id bigint, content text, metadata jsonb, similarity float) language plpgsql as $$
begin
  return query select id, content, metadata, 1 - (embedding <=> query_embedding) as similarity
  from handbook_documents order by embedding <=> query_embedding limit match_count;
end; $$;
RPC 函數讓 Workers 只要一通請求即可拿回 Top 4 相似文章 07 / 15
11-2 自動化入庫

手冊切塊與向量化藝術：scripts/ingest.js

切塊不是隨便亂切！滑動視窗切塊（Chunking）決定了 RAG 搜尋品質的一半！

✂️
1. 滑動視窗切塊

每塊大小約 300 ~ 450 字，區塊間保留 50 字重疊（Overlap）。避免因剛好切在法規句子中間而丟失前後語意脈絡！

🏷️
2. 保留 Metadata 出處

每一塊文字都附帶結構化 JSON 標籤：doc: "01_attendance"、section: "第4條 事假與請假流程"，方便 AI 引用與追溯。

🚀
3. 呼叫 Embedding 入庫

調用 Google text-embedding-004 將切塊轉為 768 維向量，使用 @supabase/supabase-js Service Role Key 批次寫入資料庫！

💬 對 AntiGravity 說的提示詞： 「AntiGravity，請幫我寫一個 scripts/ingest.js，讀取 handbooks/ 4 份 Markdown，依標題與 350 字滑動切塊，轉 768 維向量並批次寫入 Supabase！」

11-3 邊緣中繼運算

Workers 邊緣中繼：金鑰不落地與 6 步執行管線

前端網頁不碰機密金鑰，所有搜尋與 AI 調度由 Cloudflare Workers 代理完成

🔒
Cloudflare 後台環境變數 (Secrets)
  • SUPABASE_URL：雲端資料庫網址。
  • SUPABASE_ANON_KEY：前端讀取授權密鑰。
  • GEMINI_API_KEY：Google AI Studio API Key。
  • 所有密鑰皆加密儲存，員工按 F12 完全看不見！
⚡
Workers 6 步運作管線 (functions/api/ask.js)
  1. 接收前端 POST 傳來之提問 { question }。
  2. 呼叫 Google Embedding API 將問題轉為 768 維向量。
  3. 呼叫 Supabase RPC match_handbooks 抓取 Top 3 段落。
  4. 相似度門檻檢查（低於 0.65 直接回查無規章）。
  5. 組裝嚴格防幻覺提示詞呼叫 Gemini 條列作答並標註來源。
  6. 回傳 JSON 格式：{ answer, sources } 給前端展示。
