SECTION 7-2

核心兩把鑰匙：Token 與 User ID

最容易搞混的兩大參數！請嚴格確認取用位置

KEY 1 • 通行鑰匙

🔑 Channel Access Token

  • 所在位置：Messaging API 標籤頁最下方。
  • 操作：點擊「Issue」按鈕產生長字串權杖。
  • 作用：證明你的 GAS 程式有權代表此機器人發信。
  • 注意：絕不可隨意貼給陌生人。
KEY 2 • 收件地址

👤 Your User ID

  • 所在位置：Basic settings 標籤頁下方。
  • 外觀：以 U 開頭的 33 碼英數雜湊字串。
  • 作用：告訴機器人該把這則快報精準私訊給誰。
  • 常見陷阱：絕不是平日加好友的 LINE ID！

SECTION 7-3

GAS 後端核心：UrlFetchApp.fetch()

向 LINE Messaging API 發出帶有 Bearer Token 的安全 POST 請求

function sendLinePushNotification(data) { const url = 'https://api.line.me/v2/bot/message/push'; const payload = { to: LINE_USER_ID, messages: [{ type: 'text', text: `🔔 新訂單快報！\n客戶：${data.name}\n方案：${data.plan}\n電話：${data.phone}` }] }; UrlFetchApp.fetch(url, { method: 'post', headers: { 'Content-Type': 'application/json', 'Authorization': 'Bearer ' + LINE_TOKEN }, payload: JSON.stringify(payload) }); }
PUSH API CORE

推播程式 3 大核心

  • to 屬性：填入剛才取得的管理者 Your User ID。
  • Authorization 標頭：必須加上 Bearer + Token 進行身分驗證。
  • 一箭三雕整合：在 doPost 內依序執行「存試算表 ➔ 寄 Gmail ➔ 發 LINE」，零漏單！
