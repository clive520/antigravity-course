PROBLEM & BOTTLENECK

⚠️ 為什麼「單兵對話模式」一定會崩潰？

很多人習慣在同一個對話框要求 AI 做所有事情，結果往往引發三大災難：

💥

上下文塞車 (Token 膨脹)

要 AI 爬取 3 家競品規格，長篇資料直接塞爆 Memory 視窗，導致 AI 後繼無力、回答截斷或開始瞎掰胡謅。

🧠

注意力渙散 (Lost in Middle)

AI 在寫後端程式碼時，已經完全忘記了第一段提過的客群預算限制。前言不對後語，格式頻繁衝突。

⚔️

職責人格衝突 (Role Conflict)

同一個大腦無法同時扮演「吹毛求疵的資安審查員」與「天馬行空的社群文案總監」，思維彼此打架。

💡 殘酷現實：

要求單一 AI 做完「調研 + 分析 + 寫 code + 剪影片 + 算定價」，就像要求一間公司的總經理自己跑業務、管零用金又兼任大樓水電工！

CORE MECHANISM

🧩 AntiGravity 調度 Subagents 的三大基石

為什麼多代理人架構能做到又快又穩？底層原理拆解：

🛡️

1. 獨立記憶沙盒 (Context Isolation)

每位子代理都在專屬的乾淨記憶中作業。情報員看了一百篇競品規格，這些海量雜訊絕不會污染到前端工程師的代碼畫布。

🔐

2. 專用工具最小化 (Specialized Tools)

調研員只給搜尋與網頁閱讀工具；寫 code 的才給檔案修改權限。權限邊界清晰，既杜絕胡亂改檔，又確保最高資安規格。

⚡

3. 非同步平行加速 (Parallel Execution)

以往需要一個一個慢慢做的 3 份報告，指揮官一聲令下，背景開出 3 個特工同步狂飆，原本 15 分鐘的任務 2 分鐘完成！

CRITICAL ENHANCEMENT

✨ 核心亮點：為什麼需要「精準字幕產生員」？

語音轉文字（ASR）常見的兩大災難，由專屬特工徹底解決！

❌ 常見一般字幕的缺點

  • 一行太長（25~30 字）：字幕橫跨整個畫面，手機直立觀看時遮擋畫面核心主體。
  • 生硬機械斷句：在名詞與動詞中間被硬生生切開，讀起來極度彆扭。
  • 同音錯字多：專有名詞（如 ANC 降噪、OWS）常被辨識成不知所云的中文。
  • 缺乏講者區隔：雙人對談時分不清這句話是誰說的。

✔ 第三階段：精準字幕產生員的解法

  • 嚴格限長 14~18 字：每句約 1.5~2.5 秒，最適合眼睛掃讀與手機觀看。
  • 語意呼吸自然斷句：依照人類語義完整度換行，告別機器人感。
  • 專有名詞校正：修正錯字，過濾「那個、就是說」等口頭贅詞。
  • 雙人標記：自動加上 [主持人] 與 [嘉賓]，觀點對立清晰！
🚀 無縫銜接： 產出的 briefing.srt 與 podcast.srt 直接交由第五階段 FFmpeg 壓製，音訊與字幕毫秒級精確同步！
