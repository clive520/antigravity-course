4-1 工具定位

為什麼需要 GitHub CLI (gh 指令)？

GitHub 官方打造的終端機神兵利器，讓網頁操作完全被自然語言抽象化

😫 傳統手動發布的折磨

過去想要把做好的網頁上線，學員需要：

GitHub CLI (gh) 能用一行指令在雲端建庫並啟用伺服器。

更厲害的是：因為 Antigravity 具備終端機代理能力，學員連指令都不用背！你只要在中央對話框說一句話，AI 就會自動在背景替你執行所有 CLI 指令！

4-2 動口安裝

動口不動手：下指令請 Antigravity 安裝 GitHub CLI

不用到官網找下載頁面，複製提示詞交給 AI 自動處理系統套件安裝

💬 提示詞 1：請 AI 自動檢查與安裝 GitHub CLI（複製貼上）

"Antigravity，請先幫我檢查我的電腦目前有沒有安裝 GitHub CLI（gh 指令）。如果還沒有安裝，請幫我執行系統指令安裝它（例如 Windows 透過 winget，或 macOS 透過 brew），並確認是否能正常讀取版本號！"

🤖 AI 在背景替你執行的 3 大動作
  • 動作 1：檢查現有版本
    gh --version
  • 動作 2：自動執行系統套件安裝指令
    Windows 自動執行 winget install --id GitHub.cli
    macOS 自動執行 brew install gh
  • 動作 3：回報安裝成功訊息
    在對話框向你回報已就緒，學員完全不用開啟終端機手動敲指令！
4-3 安全機制

關鍵解密：Antigravity 是如何取得你的帳號資格的？

很多學員會好奇：「AI 怎麼知道我是誰？它會不會偷存我的密碼？」

❓ 學員最擔心的安全疑慮

「AI 怎麼能把東西推到我的 GitHub？」
「我要把 Google 帳號跟密碼告訴 AI 嗎？」

絕對不用！
Antigravity 本身「完全不會、也絕對不應該知道你的密碼」！

🛡️ 官方 OAuth Device Flow 安全規範

GitHub 採用全球標準的 Device Activation（設備配對驗證）：

1. 終端機會生成一組隨機的 8 碼一次性安全代碼。
2. 系統引導你開啟 GitHub 官方驗證網頁貼上代碼。
3. 你在官方網頁授權後，GitHub 派發一把加密 Token 給你本機。
4. 全程零密碼傳遞，安全等級高達 100%！

4-3 授權實戰

GitHub CLI 8 碼代碼安全配對流程（Device Activation）

只需執行一次！本機產生加密憑證 Token，從此享受終生自動推送

🔍 點擊放大全圖
▲ 圖 4-2：GitHub CLI 8 碼代碼安全配對流程（Device Activation）
步驟 1：AI 觸發授權指令

對話吩咐「請幫我啟動 GitHub CLI 登入」，終端機顯示一次性 8 碼代碼（如 ABCD-1234）。

步驟 2：官方瀏覽器開啟驗證頁

系統自動開啟 github.com/login/device，將 8 碼貼入輸入框按 Continue。

步驟 3：Google 一鍵確認授權

因為第 3 章已登入 Google，點擊「Authorize github」按鈕一鍵授權。

步驟 4：本機安全 Token 存檔完畢

高強度加密 Token 存於本機 hosts.yml，Antigravity 獲得合法推代碼權限！

4-4 命名決策

推送時的 Repo 名稱：由 AI 決定還是自己指定？

兩種都可以！完全取決於你在對話框中怎麼對 Antigravity 吩咐

🏷️ 方式 A：由自己指定 Repo 名稱（★強烈推薦）
  • 特點： 精確掌控公開網址外觀，絕不會出現意外的名稱。
  • 範例口語： 「請把專案推送到名為 smartsound-page 的公開 repo...」
  • 產生的公開網址：
    https://<帳號>.github.io/smartsound-page/
🤖 方式 B：讓 Antigravity 依專案自動命名
  • 特點： 適合不想花腦筋想英文名稱的學員。
  • 運作原理： AI 會預設使用「目前資料夾名稱」或分析網頁標題。
  • 範例口語： 「請幫我取一個合適簡短的英文名稱建立 Repo 並推上去...」
