核心原則 · THREE PILLARS

支撐自我修復的三大工程支柱

絕非憑空亂猜，而是基於嚴格的軟體工程三大基石

🎯

1. 測試驅動 (TDD)

「先立規矩，再動工實作」。
在實作核心邏輯前，先寫好魔鬼驗收測試（包含期望回傳值與極端邊界）。測試未全數通過之前，AI 絕不宣布交付！

📡

2. 終端機報錯自感知

「讀懂 Stack Trace 的訊號」。
AI 自動執行命令列，精準解析出錯檔案、出錯行號、期望值與實際值的落差，將紅字轉化為微調代碼的導航圖。

🔬

3. 最小破壞原則 (Patch)

「手術刀局部修補」。
使用精準替換工具（如 edit_file），針對性修改問題行，嚴禁整檔盲目覆寫，徹底杜絕改壞其他已通過的測試！

核心案例 · REAL PROJECT

看似簡單的「算錢功能」，藏著 4 個初學者必踩暗坑！

耳機官網計價模組 calculateTotal() 的隱藏邊界陷阱

暗坑 1

浮點數精度災難

耳機 3,880 打 9 折，JavaScript 算出 3492.0000000000005！UI 排版破裂，甚至導致金流串接失敗。

暗坑 2

滿額免運臨界點

滿 NT$ 5,000 免運費。剛好 5,000 元是免運還是收運費？邊界 >= 5000 若寫成 > 5000 就多收客人 100 元！

暗坑 3

VIP 券負數倒貼

購買 500 元配件套用 VIP888 折價券，總金額變成 -388 元！店家反而要付錢給顧客！

暗坑 4

惡意負數數量防呆

有心人士在數量欄位輸入 -2，若後端未做邊界檢查，直接造成庫存錯亂與系統異常中斷。

1. 測試先行（TDD）：在『checkout.test.js』中設計 5 組魔鬼驗收測試：
   • 單品計價與浮點數四捨五入（絕不能出現 .00000005 這種精度誤差）。

初學者寶庫 · CASE 1

【日常功能】限時特賣「24 小時倒數計時器」與過期防呆

生活痛點：活動結束後計時器繼續跑，居然倒數出「剩餘 -1 天 -3 小時」！

🎯 測試先行（TDD 設計 4 組情境）

  • 正常倒數：輸入未來 2 小時 ➔ 輸出「剩餘 02:00:00」（自動補零）。
  • 過期防呆：傳入過去時間 ➔ 顯示「活動已結束」，數值歸零絕不出現負數。
  • 邊界臨界點：剛好剩下 0 秒的瞬間，正確切換結束狀態。
  • 輸入防呆：傳入 null 或無效字串 ➔ 安全回傳預設提示，不當機。

🎁 自癒實錄與驗收成果

第 1 次運行測試時，因過去時間差計算為 -3600 秒 導致測試失敗；
AI 自主分析終端紅字，補上一行 diff = Math.max(0, targetTime - now)，第 2 次重測 4/4 綠燈全數 PASS！

✓ formatCountdown() returns 00:00:00 when expired
✓ pads leading zero correctly (02:05:09)
Tests: 4 passed, 4 total

初學者寶庫 · CASE 3

【視覺排版】商品評價「長文字摘要與『...看更多』安全截斷器」

生活痛點：短文字也被硬加看更多，甚至切斷 HTML 標籤導致全站粗體破版！

🎯 測試先行（TDD 排版邊界情境）

  • 超長文字 (100字)：截取前 50 字，並在末尾加上「... (閱讀更多)」。
  • 短文字 (20字)：完整保留原文，絕對不能出現「... (閱讀更多)」。
  • 長度剛好等於限制：精準比對邊界，不截斷也不加省略符號。
  • HTML 安全防呆：若包含 <b> 標籤，先剝離標籤再計算，避免標籤破損造成全站跑版！

🎁 自癒實錄與驗收成果

第 1 輪短文字被無條件加上後綴報錯；
AI 自主修復為 if (text.length <= limit) return text;，並用正規表達式先剝離標籤，全數 PASS！

✓ truncateText("短文字", 50) === "短文字"
✓ strips <b> tags before slicing to avoid UI glitch

資深心法 · BEST PRACTICES

自癒兩大防護網：防無窮迴圈與防回歸測試

確保 AI 自我修復不失控、歷史功能不倒退的工業級標準

🔄 🛑

1. 防無窮迴圈（重試上限機制）

「設定最大重試次數（Max Retries: 3~5）」。
若 AI 重試 3 次仍未通過，代表可能存在「規格互相矛盾」或「外部依賴缺失」。此時 AI 會誠實停下來向人類指揮官回報，絕不陷入無窮耗費 Token 的死迴圈！

🛡️ 🔁

2. 防回歸測試（Regression Testing）

「修改 bug 後，全套歷史測試全部重跑」。
這就是全綠燈的最高價值！不能只測剛才修好的那 1 個測試，必須確認過去做好的 10 個、50 個功能依然 100% 綠燈，杜絕任何隱蔽的倒退與副作用。

萬用模版 · CHEAT SHEET

自我修復迴圈萬用 Prompt 提示詞公式

任何專案都能直接套用的 4 步驟自癒指令結構

請啟動自我修復迴圈（Self-Healing Loop），為我開發【功能模組名稱】：

1.【測試先行 (TDD)】：
  在【測試檔名】中設計以下情境測試案例：
  • 正常情境：輸入 A，期望輸出 B
  • 邊界情境：剛好等於臨界點時的行為
