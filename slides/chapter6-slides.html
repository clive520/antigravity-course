SECTION 6-2

撰寫 GAS 核心接收函式：doPost(e)

監聽 HTTP POST 請求、解析 Payload、防呆檢查並呼叫 appendRow 寫入

function doPost(e) { try { const data = JSON.parse(e.postData.contents); const sheet = SpreadsheetApp.getActiveSpreadsheet().getActiveSheet(); // 寫入試算表下一列 sheet.appendRow([ new Date(), data.name, data.email, data.phone, data.plan, data.notes || "" ]); // 寄出確認信 sendConfirmationEmail(data); return ContentService.createTextOutput( JSON.stringify({ status: "success" }) ).setMimeType(ContentService.MimeType.JSON); } catch (err) { /* 錯誤捕捉與日誌記錄 */ } }
KEY CONCEPTS

核心邏輯 3 大要點

  • postData.contents：前端送來的 JSON 字串，需先以 JSON.parse() 解析。
  • sheet.appendRow()：原子化寫入新列，自帶鎖定機制防止高併發衝突覆寫。
  • createTextOutput()：務必將輸出設為 MimeType.JSON，以利前端解析。

SECTION 6-3

前端 Fetch API 非同步送單

監聽表單 submit、阻擋預設重整、鎖定按鈕防止連點

form.addEventListener('submit', async (e) => { e.preventDefault(); submitBtn.disabled = true; submitBtn.textContent = '資料傳送中...'; const payload = { name: form.name.value, email: form.email.value, phone: form.phone.value, plan: form.plan.value, notes: form.notes.value }; await fetch(GAS_WEB_APP_URL, { method: 'POST', body: JSON.stringify(payload) }); showToast('預購成功！確認信已寄發'); form.reset(); submitBtn.disabled = false; });
UX BEST PRACTICES

良好使用者體驗三部曲

  • e.preventDefault()：避免原生表單跳頁刷新的破碎感。
  • 按鈕鎖定 (Disabled)：避免使用者在網路延遲時連續瘋狂點擊，產生重複訂單。
  • 狀態即時反饋：使用 Toast 浮動視窗或成功燈號，讓使用者清楚知道訂單已完成。

SECTION 6-4

GmailApp 自動寄發個人化信件

打造專屬 HTML 郵件模板，即刻通知顧客預購詳情與訂單編號

GMAILAPP API

GmailApp.sendEmail 參數

  • recipient：收件人電子郵件（如 data.email）
  • subject：信件主旨（含訂單編號）
  • body：純文字替代備案（防止不支援 HTML）
  • options.htmlBody：精緻美觀的 HTML 排版設計
  • options.name：寄件者自訂名稱（如 NovaWave 團隊）
TEMPLATE TIPS

信件模板設計要訣

  • 內聯樣式 (Inline CSS)：郵件客戶端對外部 CSS 支援差，樣式需寫在 tag 上。
  • 訂單編號產生：以 Date.now() 搭配隨機碼產生唯一防重序號。
  • 免費用量注意：免費 Gmail 每日限制 100 封，Workspace 帳號每日 1,500 封。

SECTION 6-5

GAS 特殊行為與跨網域排錯

掌握 HTTP 302 重定向機制與 no-cors 的真實行為特徵

ISSUE 1

HTTP 302 重新導向

GAS Web App 在接收請求後會發出 302 重定向至 googleusercontent.com，瀏覽器 Fetch 預設會自動跟隨 (redirect: follow)。

ISSUE 2

mode: 'no-cors' 迷思

雖可抑制瀏覽器紅字報錯，但會將回應轉為 opaque，前端將無法讀取後端回傳的 JSON 結果，請優先確保後端正確輸出 JSON。

ISSUE 3

401 / 403 權限錯誤

百分之九十的串接失敗是因為「部署存取權限」未設為「所有人 (Anyone)」，請進入部署管理重新檢查。
