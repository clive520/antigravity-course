第 9 章 · 現代雲端邊緣部署

進階現代雲端邊緣部署：認識 Cloudflare Pages 全球極速平台

在第 3、4 章中，我們學會用 GitHub Pages 發布靜態網站。但當網站要給全公司員工使用、需要極致載入速度與更高的安全性時，全美最有影響力的雲端安全巨頭 Cloudflare 所推出的 Cloudflare Pages 便是現代開發者的升級首選！本章帶你無縫升級部署架構，跨入全球 330+ 邊緣節點的極速世界！

9-1 告別單一伺服器：從 GitHub Pages 到 Cloudflare Pages 的進化之旅

在過去，如果你的伺服器設在美國，台灣的訪客每次打開網頁都要橫跨半個地球傳送資料，延遲往往高達 200～300 毫秒（ms）。

而 Cloudflare Pages 是建立在 Cloudflare 享譽全球的 Anycast 邊緣網路 之上。當台灣使用者打開你的網頁時，資料直接由「台北或高雄的本地資料中心」瞬間送達，連線延遲大幅降低至 10～30 毫秒！

🌐 圖 9-1：GitHub Pages vs. Cloudflare Pages 現代雲端部署架構進化
從單一地區快取跨入全球 330+ 邊緣節點，不僅帶來閃電般的載入速度，更天然具備抵禦 DDoS 攻擊與原生存取控管能力。

🔥 Cloudflare Pages 的 4 大壓倒性優勢：

  • ⚡ 全球邊緣極速（Anycast Edge）：自動就近由訪客最近的城市提供網頁快取。
  • 🔄 無限流量（Unlimited Bandwidth）：免費方案不限制每月流量頻寬，完全不用擔心爆量被停機或收取超額費用。
  • 🌿 預覽分支環境（Preview Deployments）：開新分支推上 Git，Cloudflare 會自動為該分支產生一個專屬測試網址，方便團隊預覽。
  • 🛡️ 全端一體化生態系：可無縫搭配 Workers 邊緣運算、KV 儲存與 Zero Trust 企業身分驗證（這也是我們第 10 章的關鍵武器！）。

9-2 註冊 Cloudflare 與一鍵連結 GitHub 儲存庫

把現有專案轉移到 Cloudflare Pages 非常簡單，完全不用改寫任何程式碼，只需透過滑鼠在後台完成授權：

🛠️ 快速上手 3 步驟：

  1. 免費註冊帳號：前往 Cloudflare 註冊頁面，輸入 Email 與密碼完成免費開戶。
  2. 建立 Pages 專案：進入控制台左側選單的 「Workers & Pages」➔「Create application」➔ 選擇「Pages」標籤頁，點擊「Connect to Git」。
  3. 綁定 GitHub 儲存庫：授權 Cloudflare 存取你的 GitHub 帳號，並勾選我們之前建立的課程專案（如 antigravity-course）。
  4. 設定建置參數（Build settings）：
    • Framework preset：選擇 None（純 HTML 專案）。
    • Build command：留空（無需編譯）。
    • Build output directory：填入 / 或專案根目錄。
  5. 點擊 「Save and Deploy」，系統會在 10 秒內完成全球節點派發，並給你一個專屬的 *.pages.dev 正式網址！

9-3 全球 330+ 節點、免費頂級 SSL 與自訂網域

很多初學者買了自己的專屬網域（如 www.mycompany.tw）後，往往被繁雜的 DNS A 紀錄、CNAME 與 SSL 安全憑證搞得暈頭轉向。在 Cloudflare Pages 中，這些繁瑣的工序全部被自動化簡化：

🔒 自動化 SSL 與自訂網域優勢：

  • 一鍵綁定自訂網域：在專案設定中點擊「Custom domains」，輸入你的網域名稱，Cloudflare 會自動幫你配置好 DNS 與自動跳轉。
  • 全自動免費 SSL 憑證：採用企業級 Let's Encrypt / DigiCert 萬用憑證，永久自動續期，瀏覽器永遠顯示綠色安全鎖頭。
  • 自帶 DDoS 防護與 WAF 防火牆：自動過濾惡意攻擊封包、爬蟲與 SQL 注入攻擊，保障網站高枕無憂。

9-4 預覽分支（Preview Deployments）：現代軟體團隊協作神器

在傳統部署中，只要把程式碼 push 到 GitHub，就會直接覆蓋掉線上的正式網站。萬一程式有 Bug，所有線上顧客立刻受影響。

🌱 Cloudflare 的「分支即網址」黑科技：

當你在本機建立新分支進行改版時（例如 git checkout -b feature-darkmode），只要 push 上去：

  • 正式網址（main 分支）完全不受影響，顧客依然順暢瀏覽。
  • Cloudflare 會自動為該分支產生一個獨立的預覽網址（例如：https://feature-darkmode.myproject.pages.dev）。
  • 你可以直接把這個預覽網址貼給主管、同事或客戶進行驗收，確認無誤後在 GitHub 合併（Merge），正式網站才會無縫更新！

9-5 認識 Pages Functions：通往邊緣後端 Workers 的大門

這是 Cloudflare Pages 最殺手級的功能！如果你只想寫一個靜態網頁，GitHub Pages 已經夠用；但當你的網頁需要「後端運算、環境變數金鑰保護、串接 AI」時，Cloudflare Pages 原生支援 Pages Functions！

💡 只要在專案新增一個 functions/ 資料夾：

你在資料夾裡寫的 JavaScript 代碼，就會自動變成在全球邊緣節點執行的 Serverless API：

// 範例：functions/api/hello.js
export async function onRequest(context) {
  return new Response(JSON.stringify({ 
    message: "來自 Cloudflare 全球邊緣節點的問候！",
    colo: context.request.cf.colo // 顯示當前回應的資料中心代碼（例如 TPE 台北）
  }), {
    headers: { "Content-Type": "application/json" }
  });
}

這意味著你的網站**不再只是純靜態網頁**，而是具備了全端運算能力的超級平台！這也是我們在**第 10 章要串接 Supabase 與 AI 大腦的核心基石**！
