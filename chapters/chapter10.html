第 10 章 · 企業級 AI 實戰巔峰

企業級 AI 知識庫實戰：Cloudflare 全家桶 + Supabase 打造新人智慧導航庫

告別散亂在各處的員工守則與作業 SOP！本章採用全美最具實戰公信力的現代雲端技術堆疊：「Cloudflare Pages (前端) + Cloudflare Workers (邊緣後端) + Supabase (pgvector 向量資料庫) + AI API」，全程由 Antigravity 協作引導，打造一套如同「企業私有版 Google NotebookLM」的智慧問答系統——安全、毫秒反應、精準附帶手冊章節出處，查無依據絕不瞎猜！

10-1 全端架構解析：Cloudflare Pages + Workers + Supabase + AI API

新職員進公司，面對「差勤規章、請假手續、報帳規定、資安守則」散落各處，往往手足無措。我們整合這套四大核心技術，建立完整的企業知識庫閉環：

🏆 圖 10-1：企業級 RAG 現代全端四大核心架構流水線
Pages 快速載入前端門面、Workers 邊緣安全代理、Supabase 高效向量檢索、AI API 溯源生成與防幻覺。

🧩 4 大組件分工職責：

  1. Cloudflare Pages（前端入口）：放置新人智慧導航網站，極速載入、雙欄排版、提供熱門情境問題與來源查看卡片。
  2. Cloudflare Workers（邊緣安全大腦）：處理使用者的提問、將問題轉為向量、呼叫 Supabase 檢索、組合 Prompt 調用 AI API；所有 API Key 放在後端環境變數，前端完全看不到任何機密金鑰！
  3. Supabase（PostgreSQL + pgvector）：存放 4 本企業手冊的切塊內文、章節出處與 768 維語意向量，負責以餘弦相似度在幾毫秒內抓出最相關段落。
  4. AI API（Gemini / LLM）：根據檢索出來的手冊內容條列具體回答，並強制標註出處手冊與章節；找不到依據時堅決回覆「目前查不到」，徹底避免模型自行瞎猜。

10-2 知識庫核心：Supabase 建立 pgvector 與 4 本手冊切塊向量化

我們使用在專案目錄下 handbooks/ 資料夾準備好的 4 本真實企業手冊（差勤管理、出差報銷、資訊安全、福委會補助）。

🗄️ 步驟 1：在 Supabase SQL Editor 執行一鍵建表

登入 Supabase 後台，在 SQL Editor 貼上標準 SQL 語法：

-- 1. 開啟向量擴充
create extension if not exists vector;

-- 2. 建立手冊知識庫資料表
create table handbook_documents (
  id bigserial primary key,
  content text not null,                  -- 手冊切塊文字
  metadata jsonb not null,                -- 出處標籤（{"doc": "差勤管理", "section": "4.1 快篩陽性"}）
  embedding vector(768) not null          -- 768 維語意向量
);

-- 3. 建立餘弦相似度檢索預存程序
create or replace function match_handbooks (
  query_embedding vector(768),
  match_count int default 4
) returns table (
  id bigint,
  content text,
  metadata jsonb,
  similarity float
) language plpgsql as $$
begin
  return query
  select
    handbook_documents.id,
    handbook_documents.content,
    handbook_documents.metadata,
    1 - (handbook_documents.embedding <=> query_embedding) as similarity
  from handbook_documents
  order by handbook_documents.embedding <=> query_embedding
  limit match_count;
end;
$$;
💬 對 Antigravity 說的入庫提示詞（Prompt） 自動切塊與向量存庫
"Antigravity，請幫我寫一個手冊切塊入庫腳本 scripts/ingest.js：

1. 讀取 handbooks/ 目錄下的 4 份 Markdown 檔案。
2. 依照章節標題進行切塊（每塊約 300~450 字，重疊 50 字保持語意連續）。
3. 保留 metadata（包含手冊名稱、章節標題）。
4. 呼叫 Google Gemini Embedding API (text-embedding-004) 取得 768 維向量。
5. 使用 @supabase/supabase-js 將切塊與向量批次寫入 handbook_documents 資料表。

請提供完整代碼，並說明如何設定 Supabase URL 與 Service Role Key！"

10-3 邊緣運算大腦：Cloudflare Workers 處理向量檢索與環境變數

為了確保安全性，瀏覽器前端絕對不能放 Google API Key 或 Supabase 密鑰！我們讓 Cloudflare Workers 擔任最堅固的中繼站。

🔒 在 Cloudflare 後台設定安全環境變數（Secrets）：

在 Workers 專案的「Settings」➔「Variables and Secrets」加入以下變數（加密儲存）：

  • SUPABASE_URL：你的 Supabase 專案網址（如 https://xyz.supabase.co）。
  • SUPABASE_ANON_KEY：Supabase 前端讀取公開金鑰。
  • GEMINI_API_KEY：Google AI Studio 申請的 API Key。
💬 對 Antigravity 說的 Workers 提示詞（Prompt） 邊緣運算核心代碼
"Antigravity，請幫我撰寫一個 Cloudflare Workers 腳本（或 Pages Function functions/api/ask.js）：

【核心運作邏輯】：
1. 接收前端 POST 傳來的新人情境問題 { question }。
2. 使用 env.GEMINI_API_KEY 呼叫 Google Embedding API，將提問轉為 768 維向量。
3. 呼叫 Supabase 的 RPC 函式 match_handbooks，檢索出相似度最高的 Top 3 手冊段落。
4. 若最高相似度低於門檻（例如 < 0.65），直接回傳：『很抱歉，目前在內部規章中查不到相關規範，請直接洽詢人資處 (hr@example.com)！』避免 AI 瞎猜。
5. 若有相符依據，組裝 System Prompt 呼叫 Gemini 1.5 / 2.0 Flash 條列回答，並在文末附上【參考來源】清單。
6. 回傳 JSON：{ answer, sources: [{ doc, section, similarity }] }。
請提供完整、乾淨、附註解的代碼！"

10-4 打造私有 NotebookLM 前端：新人入口、引用出處與防幻覺機制

將網頁部署至 Cloudflare Pages，為新人提供如同 Google NotebookLM 般的雙欄安心問答體驗！

🖥️ 圖 10-2：私有版 NotebookLM 雙欄問答前端互動設計
左欄負責自然語言提問與結構化 SOP 排版，右欄即時對應高亮顯示吻合度最高的手冊段落與相似度分數。

🛡️ 企業級「防幻覺（Zero Hallucination）」最高原則：

  1. 嚴格接地（Strict Grounding）：AI 只被授權依據檢索到的手冊條文說話，禁止自由發揮未經查證的外部常識。
  2. 出處必標註（Citations）：回答中明確引用規章編號與章節（例如：「依據《國內外出差與費用報銷規範》第 2.1 條...」）。
  3. 誠實未知原則：手冊中沒有寫的規定（例如公司可不可以帶寵物上班），系統必須直接回答「目前查不到」，杜絕因模型瞎猜給出錯誤指導。

10-5 企業資安防護：Cloudflare Zero Trust (Access) 免費員工登入防護

如果網站不設門禁，任何拿到網址的外人都能看光手冊。傳統做法要自己寫會員登入系統，而 Cloudflare 提供完全免費的企業門禁神器：Cloudflare Zero Trust (Access)！

🛡️ 圖 10-3：Cloudflare Zero Trust Access 邊緣身分驗證架構
免寫一行登入程式！只要在後台勾選策略，未授權的訪客一律被擋在門外，僅允許具備公司信箱的在職員工存取。

🛠️ 3 分鐘設定零信任門禁：

  1. 進入 Cloudflare 控制台的 「Zero Trust」➔「Access」➔「Applications」。
  2. 點擊「Add an application」選擇你的 Pages 網址（例如：handbook.pages.dev）。
  3. 設定存取規則（Policy）：
    • 選擇「Emails ending in」，輸入你的公司郵件網域名稱（例如：@yourcompany.com）。
    • 或選擇「Email」，手動填入允許測試的同仁信箱。
  4. 完成！當任何人打開該網址，Cloudflare 會自動彈出乾淨美觀的登入畫面，輸入 Email 收到一次性 6 碼驗證 PIN 碼即可進入，**50 人以內企業完全免費！**

10-6 免費方案限制與企業 AI 資料隱私合規決策

在推動任何企業內部系統時，合格的軟體工程師必須具備「用量上限認知」與「法務資安隱私意識」：

📊 1. 免費方案額度限制與應對心法：

  • Cloudflare Workers 每日上限：免費版每日提供 100,000 次請求。內部系統每天發問幾百次綽綽有餘。若未來公司規模擴大超過上限，升級付費版每月僅需 5 美元。
  • Supabase 7 天低活動休眠與備份：
    • 免費版連續 7 天無請求會自動暫停專案；可使用 Workers 的 Cron Triggers 或 GAS 每 3 天定時 Ping 一次保持活躍。
    • 免費版無自動定時下載備份，管理者在每次更新新手冊時，建議手動在後台匯出一份 SQL 存檔備份。

⚖️ 2. 極重要！Gemini API 免費層 vs. 付費層資料隱私政策：

這是決定系統能否在公司正式上線的關鍵法務考量：

方案層級 資料隱私與訓練規範 (Data Privacy) 企業建議與適用情境
Gemini API 免費層 提交之內容可能由 Google 經過匿名化人工審閱並用於改善模型產品。 適合內部 POC 概念驗證、測試非機密之一般差勤與福利手冊。
Gemini API 付費層 (Pay-as-you-go) 零數據保留（Zero Data Retention），明確承諾不使用客戶資料訓練模型。 正式全公司上線首選！即使全公司每天使用，每月通常僅花費幾美元，享有完整法務保障。

💡 黃金策略：先以免費方案搭建與試行，驗證檢索品質與同仁反響；確認成效良好後，再在 Google Cloud 綁定信用卡切換至付費 API，並設定每月預算上限（例如上限 10 美元），既能兼顧荷包，又能享有企業最高規格資安保障！
