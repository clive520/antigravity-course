第 10 章 · 現代資料庫與 AI 向量核心

現代雲端資料庫全解：Supabase 核心功能、pgvector 向量引擎與免費額度避坑手冊

在進入第 11 章打造企業新人手冊庫實戰之前，我們必須先掌握當前 AI 全端領域最炙手可熱的後端核心——Supabase！它自稱「開源的 Firebase 替代品」，但骨子裡卻是一座無比強大、標準且絕不鎖定供應商的 PostgreSQL。本章將帶你全面剖析它的六大支柱、專為 AI 語意搜尋而生的 pgvector 向量引擎，以及免費版必學的自動休眠保活防範密技！

10-1 認識 Supabase：開源的 Firebase 替代品，真正的 PostgreSQL 核心

過去十年間，Google Firebase 是快速搭建應用程式的首選。但 Firebase 有一個讓眾多企業與開發者頭痛的硬傷：專有的 NoSQL 規格與嚴重的廠商鎖定（Vendor Lock-in），一旦資料量變大或需要複雜的關聯查詢，費用既昂貴又難以遷移。

Supabase 的誕生徹底顛覆了這個格局！它主打三大設計哲學：

🐘 真正的 PostgreSQL

不是模仿品！每一個 Supabase 專案就是一台獨立完整的 PostgreSQL 資料庫，支援 ACID 事務、標準 SQL 語法、觸發器與所有原生外掛。

🔓 拒絕供應商綁架

完全基於開源工具構建。未來隨時可以使用 pg_dump 將整座資料庫一鍵匯出，遷移至 AWS RDS、GCP Cloud SQL 或自建伺服器。

⚡ 現代全端開箱即用

省去自己寫 CRUD API 的繁瑣工序！建好資料表後，Supabase 會自動產出 RESTful 與 GraphQL API，並支援即時 WebSocket 同步。

🏆 圖 10-1：Supabase 現代雲端資料庫全景架構
以堅不可摧的企業級 PostgreSQL 為基底，整合六大雲端支柱，並具備強大的 pgvector AI 向量引擎。

10-2 Supabase 六大核心支柱功能深入剖析

Supabase 不僅僅是放資料的地方，它提供了一整套開箱即用的現代化後端基礎設施：

1. 🖥️ Supabase Studio（網頁視覺化管理後台）

告別黑底終端機的枯燥指令！Supabase 提供媲美 Airtable 與 Excel 的強大 Web GUI：

  • Table Editor：直接在網頁上增刪改查資料、設定外鍵關聯（Foreign Keys），即使是不會寫 SQL 的主管或行政人員也能輕鬆操作。
  • SQL Editor：內建 SQL 編輯器與豐富的官方腳本範本，還整合了 AI 輔助寫 SQL 查詢，一鍵點擊即可直接執行。
  • Database Roles & Schema：視覺化查看資料庫架構圖、權限角色分組與效能監控。

2. 🔐 Auth 身分驗證與 Row-Level Security (RLS)

不用自己刻註冊、登入與加密系統！

  • 多元登入管道：支援 Email/密碼、Magic Link（免密碼信件登入）、手機簡訊 OTP，以及 Google、GitHub、Apple、Azure、Discord 等 20 多種第三方 OAuth 授權。
  • Row-Level Security (RLS 列級安全性)：PostgreSQL 的企業級殺手功能！可以在資料表上直接設定原則（Policy），例如：「使用者只能讀取與修改自己 auth.uid() = user_id 的訂單資料」。即使用戶直接向資料庫發出請求，底層資料庫也會自動過濾，絕對不會外洩其他人的隱私。

3. 📦 Storage 物件檔案儲存

用來儲存大容量非結構化檔案（如使用者大頭貼、產品照片、PDF 文件、錄音音訊）：

  • 儲存桶機制（Buckets）：可分別建立公開儲存桶（Public，所有人可直接透過 URL 讀取）或私有儲存桶（Private，需搭配 RLS 授權）。
  • 內建 CDN 與圖片即時縮放：全球 CDN 加速分發，並支援在 URL 後面帶參數即時裁切與壓縮圖片尺寸（Image Transformations）。

4. ⚡ Realtime 即時資料流廣播

讓你的網頁不用重新整理（F5），就能即時看到最新的資料異動：

  • Database Changes：監聽資料庫的 INSERT、UPDATE、DELETE 事件，只要資料一變動，前端瀏覽器在幾毫秒內就能透過 WebSocket 自動收到推播！
  • Presence & Broadcast：支援使用者線上狀態追蹤（例如誰正在線上打字）與多人房聊天訊息廣播。

5. 🌍 Edge Functions 邊緣無伺服器計算

基於 Deno 運行環境的全球邊緣函數：

  • 原生支援 TypeScript，執行在離使用者最近的全球節點，近乎零冷啟動延遲。
  • 適合用來處理第三方 Webhook 回呼（例如綠界金流付款確認通知、Stripe 結帳）、發送簡訊、或是中繼 AI API 呼叫。

6. 🧠 pgvector 向量擴充引擎（AI 時代的必備技能）

在同一個 PostgreSQL 資料庫中原生儲存與比對高維度向量，詳細解析請見 10-3 小節！

10-3 為什麼它是 AI 時代的殺手級資料庫？pgvector 深度剖析

在 AI 與檢索增強生成（RAG）的世界中，如何從數萬筆文件段落中找出「語意最相關」的內容？這就是向量資料庫的職責。

🧩 啟用與宣告向量欄位：

在 Supabase 的 SQL Editor 中，只需一行指令即可啟用向量擴充：

-- 啟用向量外掛
create extension if not exists vector;

-- 建立包含 768 維向量欄位的資料表
create table handbook_documents (
  id bigserial primary key,
  content text not null,               -- 手冊原始切塊文字
  metadata jsonb not null,             -- 標籤（所屬手冊、章節標題）
  embedding vector(768) not null       -- 存放 768 維語意特徵向量
);

📐 3 大向量距離運算符號（Operators）：

pgvector 提供三個專屬的數學運算子，用來衡量兩組向量之間的幾何距離：

  • <=> Cosine Distance（餘弦距離，最常使用！）： 衡量兩個向量的方向夾角。值介於 0 到 2 之間，值越小代表語意越相近。在語意搜尋中，我們通常用 1 - (embedding <=> query_embedding) 來轉換為直觀的相似度分數（0 ~ 1 之間，1 代表完全相同）。
  • <-> L2 / Euclidean Distance（歐式幾何直線距離）： 計算兩點之間的直線空間距離。
  • <#> Negative Inner Product（負內積）： 若向量已經過正規化（Normalized），內積計算速度最快。

⚡ 向量索引加速：HNSW vs IVFFlat

當資料庫裡的手冊段落累積到數萬或數百萬筆時，逐一比對每個向量會變慢。此時可以建立向量索引：

  • HNSW（Hierarchical Navigable Small World，官方強力推薦）：建立多層圖狀結構，查詢速度極快、召回率（Recall）極高，建好後即可隨意動態寫入新資料。
  • IVFFlat（Inverted File Flat）：建立倒排聚類索引，佔用記憶體較少，但需要資料表先有一定數量的資料後再建立效果才好。
-- 建立高效 HNSW 餘弦距離索引
create index on handbook_documents using hnsw (embedding vector_cosine_ops);

10-4 Supabase 免費版額度總表與三大致命限制（避坑指南）

Supabase 的免費方案（Free Tier）非常大方，足以支撐絕大多數的中小型專題、公司內部 POC 驗證與個人作品集。但有幾項至關重要的免費限制與自動休眠規則，務必在開發前徹底弄清楚！

服務功能項目 免費版配額 (Free Tier) 實務估算與說明
活躍專案數量 最多 2 個專案 每個帳號最多同時運行 2 個免費專案。
資料庫儲存容量 (Database) 500 MB 純文字與 768 維向量約可存放數萬筆手冊段落。
Auth 活躍使用者 (MAU) 50,000 MAU / 月 每月五萬名獨立登入員工，中小企業完全不用擔心超標。
Storage 檔案庫空間 1 GB 總儲存空間 單檔上傳上限為 50 MB。
出站網路流量 (Egress) 2 GB / 月 若回傳純文字與 JSON 綽綽有餘；大檔案建議放 Cloudflare R2。

Realtime 並發與訊息 200 個同時連線 / 200 萬則訊息 足夠支撐中型即時協作或即時儀表板需求。

🚨 Supabase 免費版三大致命限制與防踩雷實戰攻略

⚠️ 致命陷阱 1：連續 7 天無活動自動進入休眠（Project Pausing）

【官方機制】：為了節省伺服器成本，Supabase 規定：若免費專案「連續 7 天沒有任何 API 請求或資料庫連線」，專案會被自動標記為 Paused 暫停狀態。休眠期間所有 API 呼叫都會回傳錯誤！雖然資料不會丟失，但你需要手動登入後台點擊「Restore project」，並等待 1~3 分鐘讓資料庫重新開機開機。

💡 破解秘技：定時心跳 Ping 保活腳本（Heartbeat）

既然 7 天無連線會休眠，我們只要利用 Cloudflare Workers 的免費 Cron Trigger（排程觸發器），或寫一段 Google Apps Script，設定每天半夜自動向 Supabase 執行一次輕量 SELECT 查詢（如 select count(*) from handbook_documents limit 1;），就能讓系統判定為「始終有活動」，專案即可永久不休眠！

⚠️ 致命陷阱 2：免費版沒有「可下載的每日自動備份（Daily Backups）」

【官方機制】：付費方案（Pro 以上）享有每日常規自動備份下載與 PITR（時間點任意還原）。而免費方案後台雖然會保持資料完整，但不提供下載備份檔（.sql / .dump）的按鈕！

💡 破解秘技：本機 pg_dump 或 Supabase CLI 定期導出

因為 Supabase 是純正的 PostgreSQL，你可以請 Antigravity 寫一個 Node.js 腳本或使用標準 pg_dump，每週自動把手冊內文與資料表結構匯出成 backup.sql 存到本地硬碟或 GitHub 私有儲存庫中，完全不用花一毛錢。

⚠️ 致命陷阱 3：容量超過 500 MB 限制時的處理

免費版資料庫上限為 500 MB。對於存放大容量檔案（如 PDF 掃描檔、大圖、影片），請絕對不要直接轉成 base64 存進資料庫欄位！正確做法是將大檔案上傳到 Cloudflare R2（免流量費） 或 Supabase Storage，資料庫資料表內只存放網址 URL，這樣 500 MB 足夠你存入數百萬字的文章與向量！

10-5 對 Antigravity 下達 Supabase 開發指令與 CLI 授權實戰

在日常開發中，除了在網頁後台點擊操作，我們更推薦讓 Antigravity 透過 Supabase CLI 或代碼腳本全自動替我們建表、做資料庫遷移與同步！

🔑 核心授權：如何讓 Antigravity 以 CLI（Supabase CLI）控制遠端資料庫？

Supabase 官方提供強大的 Supabase CLI 工具（透過 npx supabase 執行）。要讓 Antigravity 能替我們執行資料庫遷移、產生型別定義或部署 Edge Functions，需要完成以下授權：

步驟 1：取得個人存取權杖 (PAT Token)
  1. 登入 Supabase Account Settings。
  2. 點選左側 Access Tokens ➔ 點擊「Generate new token」。
  3. 複製生成的 Token（開頭為 sbp_...）。
  4. 在終端機執行一次性登入：
    npx supabase login --token 你的sbp_Token
    （或在 .env 加入 SUPABASE_ACCESS_TOKEN 達成靜默授權）
步驟 2：將本機專案連結至雲端 (Link)
  1. 至專案後台首頁取得 Project Reference ID（網址 /project/xxx 中的代碼）。
  2. 請 Antigravity 執行連結命令：
    npx supabase link --project-ref 你的專案ID
  3. 輸入建立資料庫時設定的 Database Password 即綁定完成！
💡 免安裝 Docker 的輕量腳本授權（Node.js Ingest 專用）：
若只需執行手冊向量切塊匯入腳本，只需在 Supabase 後台「Project Settings」➔「API」複製 URL 與 service_role secret，放入 .env 即可讓 Antigravity 透過 @supabase/supabase-js 以最高權限快速寫入資料！
💬 提示詞模板 1：產生建表與向量搜尋 RPC 函數 SQL 建構
"Antigravity，請幫我寫一份 Supabase 的 PostgreSQL 遷移腳本（SQL）：

1. 啟用 vector 擴充外掛。
2. 建立 handbook_documents 資料表，包含 id (bigserial)、content (text)、metadata (jsonb)、以及 768 維的 embedding (vector(768))。
3. 建立一個名為 match_handbooks 的預存程序（RPC function），接收 query_embedding 與 match_count 參數，依據餘弦相似度由高到低排序並回傳最相關段落。
4. 幫 embedding 欄位建立 HNSW 向量索引以提升檢索效能！"
💬 提示詞模板 2：自動防止 Supabase 休眠的 Cloudflare 心跳腳本 永久保活
"Antigravity，我的 Supabase 免費專案如果 7 天沒活動會自動休眠。
請幫我寫一個輕量級的 Cloudflare Workers 腳本（搭配 Cron Trigger 排程）：

1. 每天清晨 4:00 自動向 Supabase 執行一次輕量 SELECT 查詢（例如檢查手冊筆數）。
2. 使用環境變數 SUPABASE_URL 與 SUPABASE_ANON_KEY。
3. 若成功回傳 200 並記錄保活成功日誌；若失敗則發送警告。
請提供 wrangler.toml 的 Cron 設定範例與 index.js 完整代碼！"
